Brady Rutherford · its own repo
From a Forum class to a timed, attributed transcript

Every word, at the right time, next to the right person

Scribe v3 takes one Forum class and returns a transcript where each word carries its time and its speaker. It gets the words from Deepgram and the speakers from Forum's own voice log, then checks that the two clocks agree. It runs from a terminal on your Mac or from the Chrome extension, and it is the input for the On Cue pipeline.

Stage 4, up close

Lining up two clocks

Forum's log says when each person's microphone was active. Deepgram says when it heard words. They should overlap, but the video can start a little before or after Forum's "recording started" time. Scribe slides one against the other and keeps the shift where they overlap most. Try it: the demo audio runs 0.8 s ahead.

Forum: microphone active Deepgram: words heard overlap

Stage 5, up close

Every word records how its speaker was decided

forum+cluster

Forum's log and the voice both point to the same person. The strongest case, and the most common.

forum

Exactly one person's microphone was active, and the voice cluster has no owner yet.

cluster

No microphone (or several) was active, so the voice decides. Covers short gaps and edge jitter.

conflict

Forum says one person, the voice says another. A very confident voice (above 0.8) wins, which catches a hot mic picking up a neighbour.

forum-overlap

Crosstalk: several microphones on, and the voice doesn't settle it. The person with the most overlap gets it.

none

Nothing to go on: the word is "Unattributed". Never "Professor".

Using it

Two ways to run it, one engine

From a terminal (what On Cue uses)

# confirm your Forum login works
scribe me
# pull every class's records (no video)
scribe sync --out data/scribe
# transcribe one class
scribe transcribe --class 105076 --privacy ids
# check a recording's size, without printing its link
scribe probe --class 105076

Reads the Forum cookie and Deepgram key from .env, which links to ~/.minerva/.env, outside every repo.

From Chrome (the extension)

  • extension_v3/ asks Forum for the class data and the recording link from inside your logged-in tab, so your cookie never leaves the browser
  • sends the bundle to a server on your own Mac (127.0.0.1 only), which runs the same engine
  • optional, off by default: logs your own H presses in live classes, used to check the hand detector's timing

The extension hasn't been loaded into Chrome yet; its JavaScript has only been syntax-checked.

Privacy and safety

What never happens

  • Your audio isn't kept by Deepgram: every request sends mip_opt_out=true, so it's kept only while processing. It's hard-coded and tested twice.
  • Signed recording links are never written to disk or logs. Any log line has the query string removed.
  • The local video copy is deleted when a job ends, if one was needed at all.
  • Forum's hand-raise endpoint is never called. Both the command line and the extension refuse /api/v1/class-users/.
  • Anonymised mode replaces every speaker with a code like u_b968d1136a and drops name fields. Names spoken aloud stay in the text; On Cue masks those itself.
  • Secrets stay local. A pre-commit check refuses any commit that contains a key or cookie.
